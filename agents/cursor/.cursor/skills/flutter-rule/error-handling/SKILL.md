# エラーの扱い

## ログ

アプリ内部のエラーは、基本的に`dart:developer`の`log()`で記録する。`debugPrint`は使用しない。デバッグ中に一時的な値を確認する場合だけ`print`を使用してよいが、完成前に残存を確認する。

```dart
import 'dart:developer';

try {
  await repository.load();
} catch (error, stackTrace) {
  log(
    'データ取得に失敗しました',
    error: error,
    stackTrace: stackTrace,
  );
}
```

## ユーザー向け表示

- 例外オブジェクトやスタックトレースをそのまま画面に表示しない。
- エラーの詳細はログに残し、画面には状況に合う安全な日本語メッセージを表示する。
- 例は「エラーが発生しました。しばらくしてからやり直してください。」だが、通信失敗、入力不備、権限不足など、原因に応じて具体化する。
- 秘密情報、内部パス、APIレスポンス、ユーザーの個人情報をメッセージへ含めない。

## チェックリスト

- `debugPrint`が追加・残存していないか検索する。
- 失敗経路にログとユーザー向け状態の両方があるか確認する。
- UIが生の例外文を表示していないか確認する。
- ログに`error`と`stackTrace`を渡すべき例外を取りこぼしていないか確認する。
